# Practice Library: instructions for every coding agent

This file is the single source of rules for Claude, Codex, ChatGPT, and any other agent or person working in this repository. `.claude/CLAUDE.md` points here. If a rule needs to change, change it here.

## Read first

1. This file.
2. `HANDOFF.md`: current state, open questions, and who is working on what.
3. For any question, stimulus, solution, or calculator work, the authoring method in `.claude/skills/practice-library-question-author/SKILL.md` and the references it routes to. The folder is named for Claude's skill loader, but the method is plain Markdown and applies to every agent.
4. `docs/PROVENANCE.md` before claiming where anything came from, and `docs/DECISIONS.md` before changing layout, navigation, or architecture.

## Ground rules

- `src/` is the only authoring source. `dist/` is generated by `npm run build`. Never edit `dist/` by hand and never reconstruct content or design rules from it.
- Figures are generated. Edit `src/diagrams/<course>.json`, then run `npm run diagrams`. Never edit an SVG in `src/assets/diagrams/` directly.
- Keep the static SPA, course manifest, unit module, and shared-renderer architecture. Do not add question-specific branches to `src/app/`. Extend a shared renderer or data descriptor instead.
- Every question records its origin in `provenance`. Unknown historical fields stay `null`. Do not infer them from the rendered card.
- Every archetype label must be registered in `src/content/<course>/archetypes.json` with an honest status: `card`, `local`, or `review`.
- Verification language is exact. Tool checks are not human sign-off. Human sign-off is not physical fx-CG50 verification. Never claim either unless it happened and is recorded in `docs/PROVENANCE.md`.

## This repository is public

- Do not commit AP Classroom scoring-guide text, the private AP Question Archetypes library (`sources/`, `cards/`, exemplars), or any other verbatim College Board material. Card ids and scoring-guide item ids such as `SG_2.6#17` are fine; their text is not.
- Do not commit personal machine paths. Describe local sources as `~/…` relative paths, as `docs/PROVENANCE.md` does. `npm run check` fails on absolute home paths.
- Before publishing new content that was written with the private library open, run the leak scan described in `CONTRIBUTING.md`.

## Commands

```sh
npm run check            # structure, provenance, answer keys, calculator, math
npm run build            # regenerate dist/
npm run diagrams         # re-render figures (needs: pip install -r scripts/diagrams/requirements.txt)
npm run check:diagrams   # confirm committed figures match their specs
npm run preview          # serve dist/ at http://127.0.0.1:4173/
```

Run `npm run check` and `npm run build` after every content or application change, and commit the rebuilt `dist/` with the change. CI fails if `dist/` is stale.

## Working alongside another agent

- Work on a branch named `<agent>/<topic>`, for example `claude/unit-2c` or `codex/calculator-renderer`. Never push straight to `main`.
- Keep commits small and single-purpose, with messages that say what changed and why.
- Before stopping, update `HANDOFF.md`: what you finished, what is in progress, and anything the next agent must not assume. Do not rely on chat history; the next agent cannot see it.
- If you find a rule here that conflicts with the code, stop and record the conflict in `HANDOFF.md` rather than silently picking one.
- House writing style for docs and student-facing text: no em dashes, Oxford commas, varied sentence length, direct voice.
